# משימה 10 (בונוס): ציר זמן ויזואלי

**סוג:** בונוס · **מומלץ:** יחיד · **תלוי ב:** משימה 06 (segmentation) + 07 (דוח)

## מטרת למידה
המרת נתוני JSON לגרף - חיבור בין מבנה נתונים (segments) לייצוג חזותי (Gantt-style timeline).

## קלט → פלט
קלט: אותו JSON של segments ממשימה 06
פלט: תמונה (PNG) או HTML אינטראקטיבי שמוטמע בדוח של משימה 07

## ספריות מומלצות
`matplotlib` (לגרף סטטי) או `Chart.js` (ל-HTML אינטראקטיבי)

## קריטריון סיום (Definition of Done)
- [ ] כל דובר מקבל שורה/צבע קבוע משלו בגרף
- [ ] מיקום ואורך כל קטע בגרף תואמים ל-`start`/`end` בנתונים
- [ ] קטעי `unknown` מסומנים בצורה שונה/מובחנת (למשל צבע אפור)
- [ ] הגרף כולל ציר X עם יחידות זמן ברורות (שניות/דקות)
- [ ] הגרף/רכיב מוטמע בפועל בתוך הדוח ממשימה 07, לא קובץ נפרד ומנותק

## טיפים
```python
speaker_row = {name: i for i, name in enumerate(speakers)}
ax.barh(speaker_row[seg["speaker"]], seg["end"] - seg["start"],

```

## רקע והסבר מורחב

**מה זה "ייצוג חזותי" (visual encoding), ולמה זה לא סתם "לצייר יפה"?**
העיקרון המרכזי בוויזואליזציה של נתונים: כל תכונה במידע צריכה למופע חזותי ברור. כאן - **מיקום אופקי** מייצג **זמן**, **שורה/צבע** מייצג **מי הדובר**, ו**שקיפות** מייצגת **רמת ביטחון**. זו לא בחירה שרירותית - המוח האנושי טוב מאוד בקריאת מיקום ואורך (למשל, "מי דיבר הכי הרבה זמן" ניכר מיד ויזואלית), הרבה יותר מאשר בקריאת טבלת מספרים.

**למה זה נקרא "Gantt-style", ולמה זה מוכר מעולם ניהול הפרויקטים?**
תרשים גאנט (המוכר מניהול פרויקטים - "מי עושה מה מתי") משתמש בדיוק באותו עיקרון: כל "מלבן" מייצג פעילות שיש לה התחלה, סוף, ו"בעלים". כאן ה"פעילות" היא קטע דיבור, וה"בעלים" הוא הדובר. זו דוגמה נחמדה לכך שאותו רעיון ויזואלי חוזר בהקשרים שונים לגמרי - ברגע שמזהים את התבנית, קל להתאים אותה לבעיה חדשה.

**למה "אין צורך לחזור לקובץ השמע המקורי" זו נקודה חשובה ללמד?**
זו דוגמה מצוינת לעיקרון "כל שכבה עובדת רק עם מה שהיא צריכה". תחנה זו לא צריכה "לשמוע" שום דבר - כל המידע הדרוש לה (מי, מתי, כמה ביטחון) כבר קיים בצורה מובנית ב-JSON שהתקבל. זו בדיוק התועלת בחוזה API מוגדר היטב: כל רכיב יכול "לבטוח" בנתונים שהוא מקבל בלי לדעת (או לצטרך לדעת) איך הם חושבו.
