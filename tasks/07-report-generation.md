# משימה 07: הפקת דוח מודיעיני

**סוג:** ליבה (חובה) · **מומלץ:** יחיד או זוג

## מטרת למידה
הפיכת נתוני JSON גולמיים לדוח קריא למשתמש - עבודה עם תבניות (templates) ופלט מסודר.

## קלט → פלט (לפי חוזה ה-API)
`POST /report` — קלט: JSON של segments (ממשימה 06)
פלט: דוח HTML (או PDF) + JSON סיכום:
```json
{
  "total_speakers": 2,
  "total_duration_sec": 42.3,
  "speaker_breakdown": {"speaker_A": 12.4, "unknown": 17.7}
}
```

## ספריות מומלצות
`Flask`/`FastAPI` (רינדור HTML עם Jinja2), או `reportlab`/`fpdf2` ל-PDF

## קריטריון סיום (Definition of Done)
- [ ] דוח קריא מוצג: מי דיבר, מתי, כמה זמן בסך הכל
- [ ] הדוח מציג נכון גם מקרה עם דובר "unknown"
- [ ] JSON הסיכום כולל סטטיסטיקה בסיסית (כמה דוברים, אורך כולל, פילוח זמן לפי דובר)
- [ ] קלט ריק (אין segments) מטופל עם הודעה מתאימה, לא קורס
- [ ] הדוח נראה מסודר - כותרות, טבלה/רשימה ברורה, לא רק דמפ של JSON גולמי

## רקע והסבר מורחב

**למה מפרידים "נתונים" (JSON) מ"תצוגה" (דוח)?**
זו עקרון בסיסי בבניית תוכנה: תחנות 04-06 עוסקות אך ורק בעיבוד ובייצור נתונים מובנים (JSON) - הן "לא יודעות ולא צריכות לדעת" איך הנתונים יוצגו בסוף. תחנה זו (07) לוקחת את הנתונים המובנים והופכת אותם לתצוגה קריאה לאדם. ההפרדה הזו (data layer מול presentation layer) מאפשרת, למשל, לשנות לגמרי את עיצוב הדוח בלי לגעת בקוד הזיהוי - וגם מאפשרת, בעתיד, לבנות כמה תצוגות שונות (דוח HTML, אפליקציית מובייל, ייצוא ל-Excel) מאותו מקור נתונים בדיוק.

**מה זה "template" (Jinja2) ולמה לא סתם לבנות HTML עם string concatenation?**
אפשר תיאורטית לבנות HTML עם `"<p>" + speaker + "</p>"` וכו', אבל זה נהיה בלתי-קריא ומועד לשגיאות עם נתונים מורכבים. Jinja2 (מנוע התבניות המובנה ב-Flask) מאפשר לכתוב קובץ HTML כמעט רגיל, עם "חורים" (`{{ variable }}`) ולולאות (`{% for segment in segments %}`) שממלאים אוטומטית מהנתונים. זה מפריד בין "מבנה העמוד" (שנכתב פעם אחת) ל"נתונים שמוזרמים אליו" (שמשתנים בכל דוח).

**מה הופך "דוח מודיעיני" לשונה מ"דמפ של JSON"?**
הבדל מהותי: JSON גולמי מדבר למחשב, דוח מדבר לאדם. דוח טוב לא רק "מציג את הנתונים" - הוא מדגיש את מה שחשוב (מי הדובר העיקרי?), מארגן לפי היגיון (ציר זמן, לא סדר טכני), ומסתיר מורכבות לא רלוונטית (התלמיד לא צריך לראות `sample_rate` בדוח הסופי, למרות שזה חלק מהנתונים הפנימיים). זו בעצם מיומנות UX בסיסית - "מה המשתמש באמת צריך לראות מכל מה שיש לנו".
